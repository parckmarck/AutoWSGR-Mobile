# AutoWSGR Android 95% 功能对等迁移设计

**日期：** 2026-07-10

**原项目基线：** `OpenWSGR/AutoWSGR` commit `97f8b16`

**Android 基线：** `AutoWSGR-Mobile` commit `44bdeac`

**目标平台：** Android API 26+
**目标：** 将原项目已经实现的用户可见游戏自动化能力迁移到可独立运行的 Android APK，并取得不低于 95/100 的证据化功能对等分数。

## 1. 范围定义

### 1.1 纳入范围

- 游戏启动、重启、回到主页和页面间导航。
- MediaProjection 截图、横屏游戏画面归一化、无障碍点击和滑动。
- 页面、战斗阶段、模板、像素、文字、数字、地图、损伤、敌方组成和敌方阵型识别。
- 原项目战斗状态机、节点计划、敌军规则、阵型规则、路线、夜战、继续前进、撤退、迂回、战果与损伤停止语义。
- 普通战、活动战、战役、演习和决战。
- 远征、任务奖励、建造与收取、食堂做菜、浴室修理、解装和舰队切换。
- 配置档案、任务队列、定时远征、中文前端、日志、停止控制和失败截图。
- 原项目已经实现并可执行的错误恢复、船坞满处理和重复运行行为。

### 1.2 排除范围

- FastAPI、WebSocket 和电脑端 HTTP 服务外壳。
- Windows 模拟器进程发现、启动和停止。
- EasyOCR、PaddleOCR 具体桌面后端；Android 使用等价的端侧 OCR 接口。
- 原项目自身尚未实现的功能：建造资源滑块、活动 alpha/beta 入口实际切换、演习敌阵 OCR 和演习细化刷新/阵型规则/修船逻辑。
- 所有地图与所有策略组合的全排列实机测试。

排除平台外壳不等于排除底层能力。HTTP 接口背后的游戏操作、配置、任务生命周期和状态查询仍在范围内。

## 2. 对等原则

1. 每个业务动作必须能追溯到原项目 `97f8b16` 的文件、方法、常量或状态转移。
2. 不以文件数量、类数量、按钮数量、资产数量或固定成功结果计算完成度。
3. 原项目资源可以复用，业务状态和动作语义必须在 Android 后端真正执行。
4. 识别不可靠时必须阻断并保存证据，不得猜测页面后继续点击。
5. 原项目未实现的路径保持同等边界，不为追求分数创造上游不存在的业务逻辑。
6. 所有运行器使用统一的会话、取消、互斥、日志和证据机制。

## 4. 总体架构

### 4.1 工程层

- 将手工 `aapt2 + javac + d8` 构建迁移到标准 Gradle Android 工程。
- 保留现有 Java 源码，不要求整体改写 Kotlin。
- Gradle 任务必须支持单元测试、截图契约测试、APK 构建、安装和设备测试。
- 原 `build-apk.ps1` 改为 Gradle 包装入口或兼容脚本，避免存在两套不同编译语义。

### 4.2 运行会话层

建立统一 `AutomationSession` 和 `AutomationCoordinator`：

- 一个时刻只允许一个会改变游戏状态的任务运行。
- 提供开始、暂停、继续、停止和超时控制。
- 生命周期不依赖 `Activity` 是否可见；运行时由前台服务维持截图与任务。
- 每次动作记录任务、状态、页面、识别可靠度、坐标、原项目来源和耗时。
- 统一生成运行日志和失败截图，业务运行器不得各自复制 finish/cancel 逻辑。

统一最终结果：

- `SUCCESS`
- `NO_ACTION`
- `EXHAUSTED`
- `DOCK_FULL`
- `BLOCKED`
- `CANCELLED`
- `FAILED`

控制流不得解析人类可读状态文本。

### 4.3 识别层

保留并加固现有能力：

- `GameFrameViewport`、`GameFrameNormalizer` 和 `GameTouchMapper`。
- 像素规则、组合签名、模板匹配和原始 AutoWSGR 图片资源。
- 页面、战斗阶段、损伤、路线和现有数字模板识别。

新增统一接口：

- `OcrEngine`：中文、英文和数字区域识别。
- `Recognition<T>`：值、可靠度、来源、诊断详情和截图区域。
- `PageRecognizer`：页面签名与排他规则。
- `EnemyRecognizer`：敌方舰种与阵型，低可靠度时不执行规则分支。

模板和 ZIP 资产必须缓存；截图帧采用批量复制，避免逐字节与逐像素热路径。

### 4.4 页面注册与导航层

对齐原项目 14 个主要页面：

- 主页面
- 地图页面
- 出征准备
- 侧边栏
- 任务页面
- 后院页面
- 浴室页面
- 食堂页面
- 建造页面
- 强化页面
- 好友页面
- 决战页面
- 选择舰船页面
- 活动页面

`PageNavigator` 每次只执行一个边：

1. 获取归一化帧；
2. 识别当前页面；
3. 用 BFS 查找到目标页面的路径；
4. 执行第一条边；
5. 等待目标或可重规划页面；
6. 再次从步骤 1 开始。

所有边包含目标验证、超时和原项目源码引用。不得用连续固定点击代替已可识别的页面导航。

### 4.5 战斗核心

建立共用的源对等战斗引擎：

- 模式：普通地图、活动地图、战役、演习和决战单点战斗。
- 阶段：开始、前进、战况、索敌、阵型、导弹、战斗、夜战、结果、掉落、继续和结束页面。
- 节点决策：远程导弹支援、迂回、敌军规则、敌阵规则、SL 开关、阵型、夜战、继续和按舰位损伤停止。
- 计划解析器必须拒绝无法理解的有效字段，而不是静默丢弃。
- 敌军规则支持原项目当前表达式，包括布尔组合、加法、比较和兼容计划中实际出现的表达式。
- 战果、节点、损伤和舰队状态写入结构化结果，供重复条件和上下文同步使用。

## 5. 业务运行器

### 5.1 普通战

- 根据配置或前端选择解析原计划和地图资产。
- OCR 验证目标章节与地图。
- 读取每日舰船/战利品计数。
- 选择舰队；按舰船列表或规则换船。
- 战前补给、按维修模式修理、检测舰队和大破阻止。
- 按完整节点计划执行路线。
- 支持次数、间隔和“指定末节点＋最低战果”的条件运行。
- 船坞满时按配置解装或返回 `DOCK_FULL`。

### 5.2 活动战

- 进入活动页面并关闭可消除浮层。
- 识别并切换 H/E 难度。
- 选择 1 至 6 节点并进入准备页面。
- 复用普通战的舰队、补给、修理、损伤和战斗核心。
- 结束页返回活动地图并支持多次运行。
- alpha/beta 实际入口切换保持与原项目相同的未实现边界。

### 5.3 战役

- 支持简单/困难与驱逐、巡洋、战列、航母、潜艇十种名称。
- 验证难度并选择目标战役。
- 按配置修理和识别舰队损伤。
- 出征失败重试一次；仍停留在准备页时返回 `EXHAUSTED`。
- 支持指定次数、夜战、阵型和维修模式。

### 5.4 演习

- 进入演习面板并识别五个对手是否可挑战。
- 正确滚动并选择第 1 至第 5 个对手。
- 选择舰队、检测损伤并开始战斗。
- 默认按原项目单纵阵和夜战策略逐个挑战可用对手。
- 敌方阵容 OCR 保持上游未实现边界。

### 5.5 决战

按原项目宏观状态迁移：

- `ENTER_MAP`
- `WAITING_FOR_MAP`
- `USE_LAST_FLEET`
- `DOCK_FULL`
- `CHOOSE_FLEET`
- `ADVANCE_CHOICE`
- `PREPARE_COMBAT`
- `IN_COMBAT`
- `NODE_RESULT`
- `STAGE_CLEAR`
- `CHAPTER_CLEAR`
- `RETREAT`
- `LEAVE`
- `FINISHED`

功能包括章节选择/重置、票券、恢复已有进度、OCR 识别购买项、舰船/技能决策、刷新、分支前进、动态阵型、节点修理、三小关循环、船坞满解装、主动撤退和暂离保存。

### 5.6 日常操作

- 远征：主页通知、地图通知、四个槽位、结果跳过、确认重新派遣、最多八轮、定时检查。
- 奖励：主页任务通知、进入任务页、逐项收取、关闭奖励弹窗、返回主页。
- 建造/开发：选择标签、收取完成项、可选快速建造、按上游边界使用默认配方开始新任务。
- 做菜：选择 1 至 3 号菜谱、可选强制做菜、跳过动画、处理弹窗。
- 浴室：进入后院/浴室、全部修理或按名称修理、浴室满返回明确结果。
- 解装：建造页解装标签、可选舰种筛选、是否卸装备、四星确认和返回主页。
- 舰队切换：选择舰队、按名称或候选规则替换六个位置、识别最终舰队。

## 6. 配置档案系统

### 6.1 存储

用户配置保存在：

```text
Android/data/org.openwsgr.autowsgrmobile/files/configs/
```

每个档案是独立 UTF-8 YAML 文件。内置示例配置只读，用户修改内置配置时必须另存为用户文件。

应用持久保存默认档案的稳定标识。启动时：

1. 读取默认档案；
2. 完整校验 YAML、字段、规则和引用资产；
3. 在前端显示档案名称和实际路径；
4. 文件缺失或损坏时加载只读内置安全配置并显示明确错误；
5. 不覆盖、修复或删除用户原文件。

### 6.2 前端操作

- 新建空白配置。
- 从当前配置复制。
- 表单编辑。
- 高级 YAML 编辑。
- 保存。
- 另存为新配置。
- 重命名。
- 导入/导出 YAML。
- 设置为默认配置。
- 保存并设为默认。
- 删除非内置配置。
- 查看文件路径和校验错误。

表单和 YAML 使用同一个完整配置模型。表单不认识的高级字段在往返编辑时必须保留。

### 6.3 安全写入

- 文件名经过路径穿越和非法字符校验。
- 默认另存为新名称，不隐式覆盖。
- 覆盖前明确确认。
- 先写同目录临时文件，重新解析校验成功后原子替换。
- “保存并设为默认”只有在文件写入和持久化默认标识都成功后才更新当前档案。

## 7. 中文前端

默认界面分为：

1. **任务**：队列、开始、暂停、继续、停止、当前步骤和进度。
2. **作战**：普通战、活动战、战役和演习配置。
3. **日常**：远征、奖励、建造、做菜、浴室和解装。
4. **决战**：章节、轮数、舰船优先级、维修和技能策略。
5. **配置**：档案管理、表单/YAML 编辑、导入导出和默认档案。
6. **日志**：实时日志、结构化结果、失败截图和导出。

截图授权、无障碍授权和运行前提显示在首页。现有单步、自检和校准按钮移动到默认折叠的“高级诊断”，不占用主要业务界面。

## 8. 数据流

1. 用户选择配置档案和任务。
2. `ConfigRepository` 解析并校验配置及计划资产。
3. 前端创建不可变 `AutomationCommand`。
4. `AutomationCoordinator` 检查截图、无障碍、游戏安装和任务互斥。
5. `PageNavigator` 恢复并导航到业务入口。
6. 业务运行器按原项目状态机逐步识别、决策、点击和记录。
7. `AutomationSession` 返回结构化结果。
8. 日志与证据层保存配置快照、动作序列、最终状态和必要截图。

## 9. 错误与恢复

统一恢复顺序：

1. 重新截图和识别；
2. 从实际页面重新规划路径；
3. 按原项目支持的返回动作回主页；
4. 仍无法恢复时重启游戏；
5. 保存失败帧、识别详情和最后动作；
6. 返回 `BLOCKED` 或 `FAILED`，停止触控。

以下情况直接阻断：

- 截图超过时效或不可读取。
- 无障碍未启用或目标游戏不在前台。
- OCR/模板/像素结果低于该动作的可靠度门限。
- 配置字段缺失、规则无法解析或目标资产不存在。
- 计划路线与可靠识别到的当前节点不一致。
- 损伤识别不可靠或存在计划要求停止的损伤状态。
- 点击映射超出目标显示区域。

- YAML 字段、未知字段保留、规则表达式和计划路径解析。

### 10.2 截图契约测试

### 10.3 脚本化流程测试

- 普通战完整路线、条件战果和船坞满。
- 活动战 H/E 节点选择和返回活动地图。
- 战役成功、次数耗尽和修理。
- 演习五对手滚动与逐个挑战。
- 决战完整状态机、撤退、暂离和恢复。

### 10.4 模拟器验收

安装游戏和 APK 后授权截图与无障碍。至少取得：

- 一次普通战完整路线。
- 一次活动战完整路线。
- 一场战役。
- 一个可挑战演习对手。
- 一轮完整决战。
- 一次日常任务组合，其中包含远征及一个其他当前可执行操作。

若设备当天没有完成中的远征、奖励、战役次数或其他游戏条件，允许设备证明“识别无任务并安全返回”，同时用帧序列测试验证有任务分支。不得把固定成功或伪造日志作为设备证据。

## 11. 验收规则

能力单元只有同时满足以下条件才能计满分：

- 有原项目源码依据。
- Android 前端或任务队列可调用。
- 后端不是占位、空实现或固定成功。
- 自动化测试覆盖成功和失败路径。
- APK 包含并能读取所需资源。

六个业务族的代表性模拟器验收未完成时，该业务域最高获得一半分数。

最终发布门槛：

- 功能矩阵得分不低于 95/100。
- 单元、截图契约和流程测试全部通过。
- APK 构建、对齐和签名验证通过。
- 普通战、活动战、战役、演习、决战和日常任务无整个业务域缺失。
- 每项设备验收都有配置快照、日志、最终状态和证据路径。

## 12. 实施分解

本设计拆分为六个连续、可独立验收的实施计划：

1. Gradle、统一会话、结构化结果、配置档案和基础性能/并发修复。
2. 端侧 OCR、14 页面注册、BFS 导航和截图契约库。
3. 完整战斗核心与普通战对等。
